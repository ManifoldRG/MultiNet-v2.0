# Kimi k2.6 — Context-Window Ablation Analysis

**Run:** `kimictx-20260713` (2026-07-13/14). Kimi k2.6, thinking OFF, temp 0.6.
15-maze conditional set × 3 context-window settings = 45 episodes. 1 seed —
**all numbers are directional** (n=15/variant).

Compares how prior context is presented to the model:
- **`last3`** — the last 3 executed steps as decision-frame images (recency, visual).
- **`text_summary`** — a one-sentence cumulative summary of mechanism events + the movement trail (long-horizon, text).
- **`text_summary_and_last3`** — both (PR #33): summary text *and* the last-3 images.

## Headline

| variant | solved | solve% | median tok | median steps | opt-ratio (solves) |
|---|---:|---:|---:|---:|---:|
| `last3` | 8/15 | 53% | 238,180 | 89 | 0.595 |
| `text_summary` | 8/15 | 53% | 144,857 | 73 | 0.622 |
| **`text_summary_and_last3`** | **11/15** | **73%** | 154,059 | 59 | **0.650** |

**The combined setting wins on every axis** — highest solve rate (+20 pp over
both baselines), fewest steps per solve, best optimality, and ~35% fewer tokens
than `last3` (text compresses history vs 3 images/turn).

## The key result: additivity, not substitution

- **`text_summary_and_last3` strictly dominates `last3`**: it solved *every* maze
  `last3` solved, plus **3 more** (`m1_corridor_kr`, `v04_single_key`,
  `v05_single_switch`) — **0 regressions**. A Pareto improvement.
- **`text_summary` alone is a lateral move, not an improvement**: same 53% as
  `last3`, but by trading **+4 gained / −4 lost** — it solves a *different* subset,
  not a superset. On its own the compressed text loses the recency signal `last3`
  carries.
- Combining them recovers both: the summary supplies durable mechanism memory
  ("you picked up the key, opened the door…"), the last-3 images supply
  short-horizon spatial dynamics. This is exactly the PR #33 hypothesis —
  *long-horizon events as text + short-horizon dynamics as pixels is additive* —
  and it holds for Kimi.

## Where the gains land

Solve counts by maze family:

| family | last3 | text_summary | text_summary_and_last3 |
|---|---:|---:|---:|
| V (validation, 10) | 6 | 5 | **8** |
| M (keyed corridor, 1) | 0 | 1 | **1** |
| D (distractor, 2) | 1 | 1 | 1 |
| S (14×14 corridor, 1) | 0 | 0 | 0 |
| B (blind probe, 1) | 1 | 1 | 1 |

The three combined-only wins are all **mechanism mazes** (single_key,
single_switch, keyed corridor) — where remembering a past pickup/toggle *and*
seeing recent movement both matter. Pure navigation gains show up in the
validation set (6→8).

## Shared failures (no context mode helps Kimi)

Failed under all three settings: `v02_winding_corridor`, `v10_distractor_chain`,
`s5_14x14_corridor` — the longest-horizon navigation / distractor mazes. These
are Kimi capability ceilings, not context-presentation problems. Note
`last3` burned **802,966 tokens / 267 steps** thrashing on S5 to the step cap —
precisely the waste the new progress-stall watchdog (this branch) targets.

## Caveats

- n=15, 1 seed; treat as directional, rank **within** this run.
- The `text_summary` here is the *additive* form (mechanism events **plus**
  movement trail); it is **not comparable** to the earlier 540-episode sweep's
  `ctx_text_summary` (which was events-XOR-waypoints). Don't cross-reference.
- Total run cost: **9.3M tokens (~$13)**, ~7.5h on 3 Kimi workers.

## Bottom line

For Kimi on this benchmark, **`text_summary_and_last3` is the setting to use**:
it's a strict improvement over `last3` (+3 solves, 0 losses) at lower step and
token cost, and it beats the text-only summary by recovering the recency signal.
